Overview

Migration Assistant is a web-based collaboration platform for teams planning and executing infrastructure or application migrations. It lets you organize work into Plans, break each plan into Processes, and track work with Tasks, Steps, Notes, and Attachments.

Key features include:

  • Multi-user workspaces with role-based access control
  • Drag-and-drop reordering of processes and tasks
  • Rich-text and code-block step editing
  • Email notifications for process and task changes
  • System-wide audit logging
  • Responsive, branded UI
Installation
Prerequisites
  • Python 3.11 (for local development)
  • PostgreSQL 15+ (recommended for production)
  • Docker & Docker Compose (optional, recommended for production)
Local Development
  1. Clone the repository: 
    git clone https://github.com/jaywehner/migrationassistant.git
cd migrationassistant
  2. Create a virtual environment and install dependencies: 
    python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
  3. Copy the example environment file and edit it: 
    cp .env.example .env
    Set at minimum:
    • DATABASE_URL - connection string for Postgres, or SQLite
    • SECRET_KEY - a long random string
    • APP_URL - the public URL of the app
  4. Apply database migrations: 
    alembic upgrade head
  5. Start the development server: 
    python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
Production Deployment with Docker
  1. On your server, clone or pull the latest code: 
    git pull origin main
  2. Build and start the containers: 
    docker compose up --build -d
  3. The application container automatically runs Alembic migrations on startup.
  4. After code updates, always run: 
    git pull origin main
docker compose up --build -d
    Restarting an old container is not enough because it may still contain stale code.
First-Time Setup

The first time the application runs it launches a setup wizard at /setup. The wizard prompts for:

  • Application name and public URL
  • Database connection details
  • SMTP server settings (host, port, username, password, TLS/SSL)
  • Default sender name and email address

After the wizard completes, the system creates a .setup_complete marker so the wizard no longer appears. To re-run setup, remove the marker file inside the container or local data directory and restart the app.

SMTP settings can later be changed from the Admin Area without re-running the wizard.
Accounts & Login
Registration

Users can register via the public registration page. New accounts must verify their email address before they can be added to plans or receive notifications.

Multi-Factor Authentication (MFA)

After logging in, users can enable MFA from their profile area. The app generates a TOTP secret that can be scanned by any authenticator application. MFA can only be disabled by a global administrator.

Password Reset

From the login page, users can request a password reset link via email. The link is single-use and expires after a configurable timeout.

Session

Sessions expire after the number of hours configured in SESSION_EXPIRE_HOURS (default: 24). Global administrators can adjust this from the Admin Area.

Migration Plans

A Plan is the top-level container for a migration project. Every plan has a name, an optional description, and one or more members.

Creating a Plan
  1. Click Create Plan in the left sidebar or on the My Plans page.
  2. Enter a plan name and optional description.
  3. Click Create. You automatically become the plan Owner.
Editing a Plan

From the plan detail page, click the plan name or the pencil icon to edit the name and description.

Deleting a Plan

Only the plan Owner or a global administrator can delete a plan. Deleting a plan removes all of its processes, tasks, steps, notes, and attachments.

Plan Dashboard

The Analytics page shows aggregated metrics across all plans you can access, including total plans, completion rate, overdue tasks, and per-plan progress.

Members & Invites
Inviting Members
  1. Open the plan detail page.
  2. Click Manage Members (or the members icon).
  3. Enter the email address of the person you want to invite.
  4. Choose a role (Owner, Admin, Contributor, or Read Only).
  5. Send the invitation.
Roles
  • Owner - Full control over the plan, including deletion and member management.
  • Admin - Can manage members, processes, and tasks; can reopen closed tasks.
  • Contributor - Can create and edit tasks and steps; cannot manage members or delete plans.
  • Read Only - Can view plans and tasks but cannot make changes.
Accepting Invitations

Invited users receive an email with a unique link. Clicking the link adds them to the plan with the assigned role. Unregistered users who accept an invitation are guided through account creation first.

Removing Members

Owners and Admins can remove members from a plan. Removed users lose access to all plan data and stop receiving notifications for that plan.

Processes

Each plan is divided into Processes (also called tabs). Processes represent stages, workstreams, or categories of work within a migration.

Creating a Process
  1. Inside a plan, click Add Process.
  2. Enter a name and confirm.
  3. The new process appears as a tab and is automatically numbered.
Reordering Processes

Drag the handle next to a process tab to reorder it. Numbers update automatically after the new order is saved.

Renaming & Copying

Hover over or click a process tab to rename it. Processes can also be copied within the same plan or to another plan. Copying a process copies all of its tasks and steps.

Deleting a Process

Owners and Admins can delete a process. Deleting a process also deletes all tasks, steps, notes, and attachments inside it.

Email Subscriptions

You can subscribe to email notifications for individual processes. When subscribed, you receive emails for task additions, deletions, status changes, and assignments inside that process.

Managing Subscriptions
  1. From the top-right user menu, choose Subscriptions.
  2. Toggle the envelope icon next to each process you want to follow.

Alternatively, click the envelope icon on a process tab inside any plan.

A filled/gold envelope means you are subscribed. An outline envelope means you are not subscribed.
Tasks

Tasks live inside processes and represent a discrete unit of work. Each task has a title, description, status, priority, due date, assignee, and progress percentage.

Creating a Task
  1. Open a process tab.
  2. Click Add Task.
  3. Fill in the title, optional description, assignee, priority, and due date.
  4. Click Create Task.
Task Statuses

The application uses a state machine for task statuses:

  • New - Task has just been created.
  • Open - Task is ready to be worked.
  • Work In Progress - Active work is happening.
  • Waiting on Client - Blocked waiting for client input.
  • Waiting on Vendor - Blocked waiting for vendor input.
  • Ready for Migration - Work is complete and ready to be migrated.
  • Closed - Complete - Task is finished successfully.
  • Closed - Not Needed - Task is no longer required.

Closed tasks can only be reopened by Owners or Admins. Contributors can move tasks through working statuses.

Quick Close / Reopen

On the process task list, click the gold-outlined checkbox in the Actions column to close a task as complete or reopen it.

Assigning Tasks

Open a task detail page and use the Assigned To dropdown. The assignee must already be a member of the plan. If no user is assigned, no assignment notification is sent.

Task Priority & Due Date

Priority levels are Low, Medium, High, and Critical. Tasks with past due dates appear in the Analytics dashboard as overdue.

Progress

Progress is shown as a percentage and a progress bar. Closing a task as complete automatically sets progress to 100%; closing as not needed resets it to 0%.

Copying & Deleting Tasks

From the process list, click the copy icon to duplicate a task (and its steps) into another process. Click the trash icon to delete a task.

Task Steps

Steps let you break a task down into smaller instructions. Each step has a title, a rich-text description, and an optional code snippet.

Adding Steps
  1. Open a task detail page.
  2. Scroll to the Steps section.
  3. Enter a title, optional description, and optional code block.
  4. Click Add Step.
Rich Text & Code

Step descriptions support formatted text, bullet and numbered lists, links, inline code, and code blocks. The editor sanitizes content to prevent unsafe HTML.

Reordering Steps

Drag steps by the handle to reorder them. Step numbers update automatically.

Completing Steps

Click the checkbox next to a step to mark it done. The task detail page shows how many steps are completed.

Notes & Attachments
Notes

Task notes are plain-text comments visible to all plan members. Use them for status updates, reminders, or questions about a task.

Attachments

Files can be attached to tasks. Supported types include images and PDFs, which are rendered with a preview in the browser. Upload limits are controlled by the application configuration.

Email & Notifications

Email notifications keep team members informed without requiring them to check the application constantly.

Events That Send Email
  • A process is added or deleted.
  • A task is added or deleted.
  • A task status changes.
  • A task is assigned, reassigned, or unassigned.
  • A task is saved/updated (assignee notification).
  • A task is marked Closed - Complete.
Who Receives Emails

Process-level task emails go to users subscribed to the process. Assignment emails go to the affected assignee. If a task has no assignee, no assignment email is sent.

SMTP Configuration

Global administrators configure SMTP in the Admin Area. Use the Send Test Email button to confirm connectivity. A successful test proves the server can connect; it does not prove notification logic is triggered.

Account-Created Credentials

When an administrator creates a user from the Admin Area, the platform can email the user their temporary credentials. SMTP must be configured for this to work.

Admin Area

Global administrators access the Admin Area from the left sidebar. It includes:

Dashboard

Summary cards for registered users, migration plans, and recent system log entries. A full-width card shows the latest five log messages with a link to the full logs page.

Manage Users

Add, edit, disable, or delete user accounts. New administrator-created users can receive credential emails.

System Logs

View a paginated list of actions across the application. Logs include categories such as auth, plans, members, tabs, tasks, steps, notes, attachments, and admin actions. Passwords, tokens, and form text content are never written to logs.

Settings

Configure application name, public URL, session expiry, SMTP server, sender details, log level, and log retention. Retention controls how many days of system logs are kept before automatic pruning.

Roles & Permissions

The platform has two permission layers:

  • Global access level (Read Only, Normal, Admin) controls whether a user can create plans, access the Admin Area, or only view content.
  • Plan role (Owner, Admin, Contributor, Read Only) controls what a user can do inside a specific plan.

Only global administrators can access the Admin Area and manage SMTP settings. Only plan Owners can delete plans.

Troubleshooting
"Not Found" on a new page after deployment

The container may be running old code. Always deploy with docker compose up --build -d, not just docker compose restart.

SMTP test works but notifications do not arrive
  • Confirm you are subscribed to the process.
  • Check the application logs for Failed to send email errors.
  • Ensure the production container includes the latest code.
"Relation does not exist" database errors

A migration has not been applied. Run alembic upgrade head inside the container or let the Docker startup script do it.

Database connection refused locally

The default local configuration expects PostgreSQL on localhost. Either start a local Postgres server or change DATABASE_URL to point to an available database.

FAQ
Can I use SQLite?

SQLite can be used for local development, but PostgreSQL is required for production because the application uses PostgreSQL-specific features such as native enums and the subscription/log tables.

Can I customize the colors or logo?

The application uses a central theme file at app/static/css/theme.css. A separate CPC_Theme folder is provided for theme-building experiments and is not referenced by the application code.

What happens when I delete a task?

Deleting a task removes its steps, notes, and attachments permanently. Subscribed users receive an email notification.

Can a contributor reopen a closed task?

No. Only plan Owners and Admins can transition a task out of a closed status.
